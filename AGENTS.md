# AgentControl — contributor guide

> Working rules for contributing a PR to this repository (humans and
> agents alike). The full **maintainer** workflow — orchestrated-agent
> internals, release mechanics, deployment, hook configuration — lives
> in [docs/maintainer.md](docs/maintainer.md); it documents the
> maintainer's own automation and does not apply to your clone.

## Project layout

- `crates/daemon` — `agentcontrol-daemon`: session manager, ACP
  server, backlog orchestrator, embedded web UI.
- `crates/acctl` — CLI client; `crates/proto` — shared protocol
  types; `crates/forgesync` — forge sync; `crates/acp-claude`,
  `acp-core` — ACP adapters; `crates/client-core` — shared client
  logic.
- `client/` — desktop & Android app: `src` web UI (TypeScript),
  `src-tauri` Tauri shell; `client/tools` — release & versioning
  scripts.
- `skills/` — agent skills shipped inside the daemon binary
  (`skills/<name>/SKILL.md`).
- `packaging/`, `docs/`, `.devin/hooks/` — install assets,
  internals docs, repo-local policy hook examples.

## Build & test

- `cargo build --release` — daemon + CLI; `cargo test --workspace`
  (the `rust` CI job gates merges on it).
- Touched `client/`? `cd client && npm run build` (tsc + vite);
  `client/src-tauri/` → also `cd client && npm run check`.
- Full app bundle: `cd client && npm install && npx tauri build`.

## Pull requests

- **Every feature/fix PR targets `next_release`** (`gh pr create
  --base next_release`) — `main` is only fed by releases.
- Conventional-commit subjects (`feat:`, `fix:`, `chore:`…); PRs are
  squash-merged.
- A user-visible `feat`/`fix`/`perf` PR adds one line to
  `client/tools/release_notes_en.txt`: `<PR number>: <english note>`
  (`<PR>: [skip] <reason>` for internal changes).
- CI builds all artifacts on PRs; the required checks are the
  `daemon-linux` ×2, `client` ×2, `client-android`, `client-macos`
  build jobs plus `rust` (test.yml) — `js`/`audit` stay advisory.

## Automatic versioning

- **No per-PR version bump** — versions move at release only. The
  bump level comes from **parenthesized keywords in commit
  subjects**: `(sync)` → minor (blocking client↔daemon protocol
  breakage — the *only* minor trigger), `(major)` → major
  (exceptional), nothing → patch. `(minor)` is deprecated and
  treated as patch.
- The keyword rides in the **squash commit subject** — keep it in
  the commit subject itself; a keyword only in the PR title never
  reaches the cycle. Source of truth: `client/tools/bump_version.py`
  (`detect_level`).

## Code conventions

- Quality and evolvability first — clear abstractions and readable
  code over quick hacks.
- Files ≤ ~1000 lines — split coherent modules past that.
- Tests: favor integration coverage of real flows (daemon ↔ client,
  ACP, SSH); no mandatory unit-test quota.

## Known pitfalls

- `anyhow::bail!` in a `Result<_, String>` function → E0308.
- `ureq` needs its `tls` feature (rustls) for https — `native-tls`
  is a custom connector, never the default backend.
- `gen/android` is NOT committed — generated by the `client-android`
  CI job.
- Tauri 2: `set_var` is `unsafe`; `get_webview_window` requires
  `use tauri::Manager`.
- Never stop/restart/replace a running `agentcontrol-daemon` — it
  hosts live agent sessions; redeployment is the maintainer's job.
